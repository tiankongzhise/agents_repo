# 功能规格

## 核心文档颗粒度标准

### 背景

中央规则已经要求默认维护 PRD、DESIGN、TECH、SPEC、AGENTS 和 DEVELOPMENT_PLAN，但缺少每份文档应详细到什么程度的判断标准。结果容易出现两类问题：文档过粗，无法指导实现和验收；或文档过细，重复代码和制造维护成本。

### 规格

- `AGENTS.md` 必须声明核心项目文档遵循“最少充分、可验证、可交接”的原则。
- `PRD` 的最低颗粒度必须覆盖用户目标、用户角色、场景、范围、功能需求、非功能约束、验收标准、依赖、风险、待确认问题和 deferred 项。
- `DESIGN` 的最低颗粒度必须覆盖体验目标、信息架构、流程、页面/组件或交互状态，以及空、错、加载、权限、可访问性和视觉约束；无前端影响时写明无影响。
- `TECH` 的最低颗粒度必须覆盖架构决策、模块边界、数据模型、接口契约、外部依赖、配置环境、迁移部署、安全隐私、性能、观测日志、失败处理、官方依据和关键取舍。
- `SPEC` 的最低颗粒度必须覆盖输入输出、状态流转、校验规则、错误处理、权限、边界条件、数据字段、接口或事件契约，并追溯 PRD 条目。
- `DEVELOPMENT_PLAN` 的最低颗粒度必须覆盖任务拆分、顺序、依赖、影响文件或模块、执行者、状态、验证命令、测试覆盖、文档更新、阻塞点和 deferred 后续项。
- `AGENTS.md` 的职责必须限定为可复用协作约束、项目惯例、命令、环境坑点和安全边界，避免承载一次性产品需求或临时计划。

### 验证规则

- 每个 PRD 有效需求必须能在 SPEC 或 DEVELOPMENT_PLAN 中找到对应实现项，或明确标记为 deferred。
- 任一新增需求如果对设计、技术或 AI 协作约束无影响，必须在 SPEC 或 DEVELOPMENT_PLAN 中说明无影响及原因。
- 更新任一核心文档后，必须检查其他相关文档是否存在矛盾或漏项。

### 无影响说明

- 本次变更不修改 `agents-md-sync` 同步命令、发布授权逻辑或中央仓库分支命名规则。
- 本次变更不新增运行时代码依赖、UI、API、数据迁移或部署影响。

## AGENTS 同步授权优化

### 背景

原同步流程只通过 `auto_publish_on_agents_change` 判断是否发布，但该字段更像功能开关，不足以证明用户已授权当前项目把 `AGENTS.md` 推送到中央仓库。运行时推送命令仍可能因为审批策略被拒绝，导致中央仓库无法接收本地规则更新。

### 规格

- 新增项目内发布授权字段 `publish_authorization`。
- 安装、初始化或首次使用 `agents-md-sync` 时，如目标项目没有有效授权，必须显式询问用户是否授权发布。
- 用户授权后，写入 `.agents-sync.json`，并保留已有配置字段。
- 发布前必须校验授权字段；授权缺失、不匹配或已撤销时跳过发布。
- 推送命令如仍需运行时审批，审批说明必须包含已存在的项目内授权、中央仓库和目标分支。

### 无影响说明

- 本次变更不新增运行时代码依赖。
- 本次变更不改变中央仓库分支命名规则。
- 本次变更无 UI、API、数据迁移或部署影响。
