# 设计说明

## 核心文档颗粒度标准

本次变更只影响开发协作文档，不新增产品界面、页面、组件或用户交互。

### 文档体验目标

- 读者能快速判断每份核心文档负责回答什么问题。
- 文档标准足够明确，能指导 AI 助手或开发者把需求、规格、技术方案和计划更新到可交接程度。
- 规则不过度模板化，允许不同项目按复杂度调整篇幅。

### 信息结构

中央 `AGENTS.md` 在“文档权威与同步”章节中集中描述文档职责：

- `PRD` 说明用户目标、业务范围和验收标准。
- `DESIGN` 说明体验、流程、界面和状态设计。
- `TECH` 说明架构、依赖、接口、数据、安全和运维取舍。
- `SPEC` 说明可实现、可测试的功能规格。
- `DEVELOPMENT_PLAN` 说明任务拆分、顺序、状态和验证。
- `AGENTS` 说明长期协作约束和环境惯例。

### 状态覆盖

无前端状态、加载状态、错误状态、权限状态或可访问性变更。本次只要求后续有前端或交互影响的需求在 `DESIGN.md` 中覆盖这些状态；无影响时必须明确写明原因。

### 视觉与交互影响

无视觉、布局、导航或交互影响。
